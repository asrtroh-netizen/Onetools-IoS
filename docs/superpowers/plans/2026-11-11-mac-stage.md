## M2 复核这 12 小时的 Swift 单测

脚本：`scripts/mac/40-verify-windows-work.sh`。

```sh
bash scripts/mac/40-verify-windows-work.sh
```

脚本开头仍是「未在 Mac 上运行」。本机只做了 `bash -n`，没有跑 `xcodebuild`。命令写在脚本里：

| 命令 | 角色 |
|---|---|
| `swift test --package-path _harness/ClashLogic` | 预期。这个包只依赖 Foundation |
| `swift test --package-path SigningLogic` | 预期。WSL 已核对 13 项、0 失败（`ExpiryReminderTests` 9 项、`BatchTests` 4 项，见 SP-09）。Mac 上再跑 |
| `swift test --package-path OneUI` | 对照。`OneUI/Package.swift:11` 的 macOS 分支 `:14` 是 iOS 15，`:28-31` 已有 `OneUICoreTests`。WSL（Linux 分支）在部分 E3（`f28e45c`）之后是 `Executed 7 tests, with 0 failures`：骨架 3、tokens 1、字号 / 底栏 / 水波纹各 1。图标仍阻塞，不是 E3 全部通过。总计划 P4：Mac 主机上的 `swift test` 会去编 macOS，所以这条不是预期路径 |
| `xcodebuild build -scheme OneUI -destination 'generic/platform=iOS'` | OneUI 的预期编译。未在 Mac 上运行 |
| `xcodebuild test -scheme OneUI-Package -destination 'platform=iOS Simulator,name=<本机 simctl 里的 iPhone>'` | OneUI 的预期测试。机型名由 `xcrun simctl list devices available` 取第一条 iPhone，不写死。未在 Mac 上运行 |

`OneUI-Package` 这个 scheme 来自总计划 P4。包内已有 `OneUICoreTests`，scheme 是否生成要到 Mac 上才知道。scheme 不存在的话这一步会失败，先补 scheme 再重跑。14 个界面文件仍未改。4.2–4.9 界面层、这两条 `xcodebuild`、G4 仍未做。

脚本回显 `docs/autorun/REPORT.md` 第 3 节的未编译清单，以及 ClashtvOS 注意事项：未改 `ClashtvOS` 的 `project.yml`；`ConfigTransforms.swift` 若 `import ClashClientUI`，未依赖该包的 ClashtvOS 会编不过。本脚本不改 `project.yml`，不代编那份清单。

## M3 Clash-Client 原版，以及「Swipt 兼容」

总计划 T2.2、T3.5。脚本：`scripts/mac/20-clash-client.sh`。

```sh
bash scripts/mac/20-clash-client.sh
```

脚本依次做：

1. `python3 -m venv .build/python-env`，并 `source .build/python-env/bin/activate`
2. `python3 -m pip install PyYAML`
3. `python3 scripts/bootstrap.py`
4. `python3 scripts/configure.py --bundle-base "$BUNDLE_BASE" --team "$TEAM_ID"`

`configure.py` 会改写 `apple/ClashClient/project.yml`，然后调用 `xcodegen generate`，再调用 `scripts/build_cli.py`（`go build` 出 `clash-cli`）。脚本本身不调用 `xcodebuild`。

bootstrap 预期最后一行：

```text
Public dependencies verified. Run python3 scripts/configure.py, then build an app scheme.
```

脚本成功之后，手工做完 T2.2 剩下的检查：

- `rg -n "LoopbackAddress" Clash-Client/.build/dependencies/kernel/listener/config/tun.go`，预期至少一处
- 看 `Clash-Client/.build/dependencies/kernel/third_party/sing-tun/` 下有没有 `ip_rewrite.go`，记入 `docs/decisions/G1-bringup.md`
- 按总计划 D8，从 `ClashiOS` 的 entitlements 去掉三个 iCloud 键：`com.apple.developer.icloud-services`、`com.apple.developer.icloud-container-identifiers`、`com.apple.developer.ubiquity-container-identifiers`，然后重新跑 `configure.py`。`configure.py` 每次用 PyYAML 重写 `project.yml`，按 target 名和键名找，不按行号
- 在 Xcode 里编 `ClashiOS` 并装机。能导入订阅、连接、打开网页。记下扩展进程常驻内存

然后做 T3.5（总计划 T2.3）：`swift test`（`ClashClientUI` 目录）、编 `ClashiOS`、装机核对 `loopback-address`。

## M4 Swipt、Feather 原版各跑通一次

总计划 T2.4、T2.5。得到闸门 G1 的基线。

Swipt：

```sh
bash scripts/mac/30-swipt.sh
```

脚本先确认 zipball 已就位，再在 `Swipt/` 里执行 `make lib`、`bun dev frameworks`、`make build_ios`。不要跑 `git submodule update`。`DeveloperDiskImage` 的仓库路径是 `Swipt/Swipt/Resources/DeveloperDiskImage`（`Swipt/.gitmodules` 的 path 是 `Swipt/Resources/DeveloperDiskImage`，相对 Swipt 仓库）。对照 `docs/findings/submodules.md` 与 `.mimocode/r0-6-submodules-ready.txt`：6 个文件、18,046,187 字节，没有 `.git`。标记文件是 `README.md`、`Image.dmg`、`BuildManifest.plist`、`Image.dmg.trustcache`、`Image.dmg.root_hash`、`Image.dmg.cryptex_info`。文件都在就打印现状并跳过拉取；缺任一个就打印说明并失败。装机和 LocalDevVPN 基线按总计划 T2.4 手工做：配对成功，装上「跳过中国广告」，开一个有开屏广告的 App 看它跳过。`Swipt/CLAUDE.md` 里已有装机命令 `bun dev install`。

Feather：

```sh
bash scripts/mac/35-feather.sh
```

脚本确认 `Feather/Zsign` 的 `README.md`、`Package.swift`、`LICENSE` 和 `Feather/IDeviceKitten` 的 `README.md`、`Package.swift`、`LICENSE` 都在，打印文件数后停住，不编译，也不要跑 `git submodule update`。对照同上两份记录：Zsign 247 个文件、29 个目录、73,644,372 字节；IDeviceKitten 25 个文件、13 个目录、46,693 字节。两个目录都没有 `.git`。缺标记文件就打印说明并失败。

打印：

```text
先读 Zsign/README.md 和 IDeviceKitten/README.md 再决定怎么编译。本脚本到此为止，不编译。
```

README 已在本机。`docs/findings/submodules.md` 已核对：给 Feather 用的 Zsign 要现编源，不是盘上的 Windows `.lib`；IDeviceKitten 这份快照没有 Rust 源，`IDevice` 是 `Package.swift` 里的远程 `binaryTarget`，预编译 xcframework 不在盘上。读完再决定怎么编，记下来。上游 `Feather/Makefile` 存在，它的 `clean` 和 `deps` 会删构建目录，并从 `https://backloop.dev/pack.json` 取证书；本脚本不调用 `make`。

装机预期：导入证书和描述文件，签一个测试 IPA 并装上，App 能打开。
